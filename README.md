# EcoLoop

A self commissioning supervisory controller for building HVAC, closing the loop against a
live EnergyPlus instance through its runtime API.

Point it at a building model. It discovers what can be actuated, measures where the energy
goes, trials each candidate measure against the untouched baseline, deploys what earns its
place, and refuses when nothing does. Control is written into the running simulation every
timestep; an open-source LLM supervises the controller from a day-ahead forecast; every
number below is regenerated by one command.

**Headline, full year, DOE reference medium office, Chicago:**
**−5.33% electricity, −8.66% peak demand, with unmet hours lower than baseline** (51.5 vs
56.0) and comfort held to +0.7% degree-hours against a band the controller cannot move.

## Quick start

```bash
make setup
```

Installs EnergyPlus 26.1.0 to `~/opt/EnergyPlus-26-1-0` (no sudo, ~1 GB) and creates a
virtualenv. Requires Python 3.11+, macOS (arm64/x86_64) or Linux (x86_64/arm64).

```bash
make smoke
```

3-day closed-loop run, ~1 s. If this prints KPIs, everything below will work.

**Ollama is not required.** The agent arm replays from a committed decision journal of 390
records. Install it only to generate new decisions:
`ollama pull qwen2.5:3b-instruct`. Override with `ECOLOOP_LLM_MODEL` / `ECOLOOP_LLM_HOST`.

## Reproducing every published number

```bash
make evidence
```

**≈3 minutes, no model server needed.** Runs the complete ablation ladder over two climates
and four periods, commissions all three building-and-climate pairs, and writes:

- [`docs/evidence/evidence.json`](docs/evidence/evidence.json) — every figure, machine-readable
- [`docs/evidence/report.html`](docs/evidence/report.html) — the rendered report, self-contained

Nothing in the report is transcribed. It is rendered from the same objects the simulations
returned, so a figure in this file and a figure in the repository cannot disagree.

To prove the agent arm needs no model at all, run it against a dead port:

```bash
ECOLOOP_LLM_HOST=http://127.0.0.1:9 make evidence
```

Individual pieces, if you would rather not run the whole thing:

| command | what it does | time |
| --- | --- | --- |
| `make compare` | ablation ladder, full year, all five arms | ~60 s |
| `make agent` | baseline vs deterministic vs model-supervised | ~35 s |
| `make commission-matrix` | all three commissioning cases | ~2 min |
| `make test` | 55 tests, including real simulations | ~55 s |
| `ecoloop decisions agent` | what the model decided each day, and why | instant |

## Results

### Ablation ladder — full year, Chicago, identical clock

Arms run in separate processes on identical weather, run period and timestep, aligned on a
time index that is *asserted* identical.

| arm | kWh | peak kW | unmet h | outside band h | degree-hours |
| --- | --- | --- | --- | --- | --- |
| B0 baseline | 767,959 | 344.9 | 56.0 | 507 | 1,030 |
| B1 deadband, unguarded | 761,115 (−0.89%) | 340.4 (−1.31%) | 231.3 | 4,891 | 1,715 (+67%) |
| **B2 supervisor** | **727,003 (−5.33%)** | **315.1 (−8.66%)** | **51.5** | 514 | 1,037 (+0.7%) |
| B3 foresight bound | 731,092 (−4.80%) | 315.1 (−8.66%) | 50.0 | 505 | 1,015 (−1.4%) |
| B4 agent, model-supervised | 756,427 (−1.50%) | 340.4 (−1.31%) | 55.0 | 509 | 1,033 (+0.3%) |

**B2** resets supply air temperature after ASHRAE Guideline 36 and never touches a
thermostat. It returns six times the energy of the naive deadband arm for a hundredth of the
comfort cost, and lowers unmet hours below baseline while doing it.

**B3** is not a controller worth shipping — it is the same loop given the day's forecast peak
instead of the current reading, on the same degraded forecast the model gets. Over a single
season it lands on B2 to within 0.03 points; over a year it trades 0.5 points of energy for
22 K·h of comfort. **Anticipation has no headroom to find on this measure**, which is why B4
does not beat B2. Against B0 alone, B4 saves 1.5% and could be reported as a success; that is
only visible as a non-result because B2 and B3 exist.

### By season, Chicago

| --- | --- | --- |

| shoulder | −1.43% | −0.03% |

### Commissioning matrix

| | medium office, Chicago | small office, Chicago | medium office, Delhi |
| --- | --- | --- | --- |
| conditioned zones | 15 (3 VAV loops) | 5 (packaged single-zone) | 15 |
| electric reheat | 18.5% | 0.0% | 1.2% |
| fans | 2.6% | 16.6% | 3.2% |
| `supply_air_reset` | tried: −5.33% → **deployed** | no handle in this model | below 3% threshold |
| `hvac_availability` | below 3% threshold | tried: **+2.14%** → rejected | tried: +1.11% → rejected |
| **outcome** | supply air reset | **deploys nothing** | **deploys nothing** |

The small office column is the one that matters. Fans dominate it, its availability schedule
is actuable, and running fans only when occupied still made the building **worse** — fan
energy alone rose 12.5%, because releasing the schedule hands the system to its
`AvailabilityManager:NightCycle`, which cycles harder than the schedule it replaced. Nothing
in the load breakdown or the control surface predicts that. Only a trial catches it, so the
system deploys nothing and says why.

Delhi explains an earlier result from first principles: the same controller returns −0.59%
there over a year because heating is 1.2% of electricity against 18.5% in Chicago.
Commissioning declines the deployment in advance.

## How it works

Full detail in **[ARCHITECTURE.md](ARCHITECTURE.md)**, which covers the four topics the brief
asks for — tool-calling, prompt engineering, latency management, and handling lengthy
simulation logs — with measured figures for each.

In short:

- **Closed loop.** Two runtime callbacks per timestep against a live instance: read state and
  write actuators on the way in, record telemetry on the way out. An annual run is 52,560
  timesteps in 14 s.
- **`Policy` is the contract** between whoever decides strategy and the machinery that
  executes it. The deterministic author and the model emit the same object.
- **Three timescales.** Per-timestep deterministic execution, 30-minute deterministic
  re-planning, daily model supervision. The model is never in the inner loop: 52,560
  inferences a year at 7.6 s each is 111 hours against a 14-second simulation.
- **Guardian.** Every policy is clamped into a fixed comfort band before it reaches the
  instance, and every clamp is counted.
- **Nothing waits on inference.** A slow, unreachable or malformed reply keeps the last good
  plan; with no plan at all the deterministic curve drives the building.

### MCP interface

13 capabilities defined once in `ecoloop/tools.py` with no MCP import; `mcp_server.py` is
registration only. The in-process agent calls them directly, external clients reach the same
functions over the protocol, so the two cannot drift.

```bash
make serve        # stdio
make inspector    # MCP Inspector
```

`ecoloop serve --http` speaks streamable HTTP on port 8000. To attach a desktop client:

```json
{
  "mcpServers": {
    "ecoloop": {
      "command": "/absolute/path/to/repo/.venv/bin/ecoloop",
      "args": ["serve"]
    }
  }
}
```

`evaluate_policy` closes the loop from outside the codebase — propose a policy, run it, get
it scored against a cached baseline in 1–2 s.

## Measuring comfort

Two metrics, because the obvious one is gameable.

*Unmet hours* are measured against whatever setpoint the controller currently commands, so a
controller that widens its own band improves its own score. A zone held at 29 °C while
commanding 30 °C reports **zero** unmet hours; `tests/test_kpi.py` pins that down.

*Comfort excursion* is occupied time outside a fixed 21–24 °C band taken from the baseline's
own occupied setpoints, reported as hours and as degree-hours. The controller cannot move it,
and the Guardian clamps occupied setpoints back inside it before they reach the instance.

Both are reported for every arm. See
[ADR 0004](docs/adr/0004-comfort-scored-against-a-fixed-band.md).

## Ifff anyone extending this

Four EnergyPlus API constraints produce **wrong numbers with a zero exit code** rather than
an error, and all four bit us:

- Output variables must be requested before the run starts.
- Handles are invalid until `api_data_fully_ready()`.
- Warmup *and* sizing-period environments must both be discarded — filtering `warmup_flag`
  alone is not enough, and our first run benchmarked two design days by mistake.
- `minutes()` and `current_time()` report the *system* timestep, which subdivides adaptively.
  Timestamps built from them differ between arms on the same clock. `zone_time_step_number`
  is the uniform one.

Two more of the same kind: `Electricity:Facility` has no API handle in 26.1 (meters resolve
from a candidate list, and a missing required meter raises rather than reporting zero), and
supply air temperature must be reset through the **schedule the setpoint managers read**, not
the supply node — overriding the node moves the reported setpoint and changes nothing else.

Provenance: models and the Chicago EPW are copied unmodified from the EnergyPlus 26.1.0
distribution. The New Delhi file is ISHRAE 2014 data from climate.onebuilding.org, licence
committed alongside it.

Delhi results are a climate-sensitivity probe, not a claim about Indian buildings — the US
prototype run on Delhi weather shows 540 baseline unmet hours against 56 in Chicago and is
undersized for that climate. A real claim needs an ECBC-compliant model.
